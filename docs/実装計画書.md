## 0. 使い方（Build フェーズ向け）

### 0.1 作業の進め方

1. **Phase 順を守る**（0 → 1 → 2 → 3 → 4 → E）。依存のため飛ばさない。
2. 各 Phase 内は **Step 番号順**に実施する。完了目安を満たした Step のステータスに **必ず** `〇` を付ける（§0.3）。コード実装だけで終えず、**同一作業内で本ファイルを更新**する。
3. 各 Phase 末尾の **完了ゲート**を満たしてから次 Phase へ進む。あわせて §0.4 の Phase ステータスも更新する。
4. **完了報告・チャット終了の前に**、指定範囲の Step／Phase ステータス更新が済んでいることを確認する。未更新のまま「完了」としない。
5. **実 AWS デプロイ（`sam deploy` 等）は、Phase E 完了まで禁止**。

### 0.2 範囲指定の記法

Build 開始時に次のいずれかで範囲を指定できる。

| 指定例 | 意味 |
|--------|------|
| `Phase 0` | 骨格のみ |
| `Phase 1` | Phase 1 の全 Step（P1-1〜） |
| `Phase 1–2` | Phase 1 と 2 |
| `P1-1`〜`P1-4` | Phase 1 の API 側のみ、など |
| `Phase E` | 横断 E2E・受け入れのみ（前提 Phase 完了後） |
| 指定なし | Phase 0 から順に可能な範囲まで |

未完了の先行 Step に依存する作業は実施しない。

### 0.3 Step ステータス（進捗の目視用）

各 Step 表の **ステータス** 列は、マス幅を保ったまま次の表記にする。

| 値 | 意味 |
|----|------|
| （空白） | 未着手（初期値。セルは空欄） |
| `〇` | 完了目安を満たした印。**実装が正常完了したらそのターンで必ず付ける**（後回し禁止） |

各 Phase 末尾の **完了ゲート**も同様に、未完了は `- [ ]`、完了したら `- [〇]` とする（Markdown の `[x]` は使わない）。

エージェント／開発者は、指定範囲の実装完了時に本節と §0.4 を更新してから完了報告する（`AGENTS.md` §6 も参照）。

### 1.3 Plan 仮置きの実装固定値

| 項目 | 固定値（実装で従う） |
|------|----------------------|
| 認証 | なし |
| 一覧 | Scan 全件。フィルタ・ページングなし |
| エラー JSON | `{ "message": "<string>" }` |
| DELETE 成功 | `204 No Content`（ボディなし） |
| PUT | 全置換。`title`/`body`/`author` 必須（非空）。`tags` 省略時は `[]`。`memoId`/`createdAt` 不変 |
| 一覧表示順 | サーバ非保証。**フロントで `updatedAt` 降順** |
| 単一取得 API | **追加しない**。詳細は一覧選択時の状態＋更新レスポンス |
| 削除 UI | 確認ダイアログ必須 |
| 同時更新 | 最後の書き込み優先 |
| `memoId` | UUID 文字列（例: `uuid.uuid4()`） |
| 作成後 UI | **一覧へ遷移／一覧再表示** |
| 日時 | ISO 8601 UTC（末尾 `Z` 推奨） |

### 1.4 バリデーション数値（U-03 仮置き）

レビューで変更可。変更時は要件定義書へ反映する。

| フィールド | 規則 |
|------------|------|
| `title` | 必須。trim 後 1〜200 文字 |
| `body` | 必須。trim 後 1〜10000 文字 |
| `author` | 必須。trim 後 1〜100 文字 |
| `tags` | 任意。配列。各要素は trim 後 1〜50 文字の文字列。最大 20 個。空文字要素は拒否。省略／`null` は `[]` |
| `memoId`（パス） | 必須。非空文字列（形式チェックは UUID 推奨だが、存在確認は DynamoDB） |
| JSON Body | 不正 JSON → `400` |
| 想定外メソッド／パス | `404` または `405`（どちらかに統一。推奨: パス不一致 `404`、メソッド不一致 `405`） |

### 1.5 成功時 HTTP ステータス（固定）

| 操作 | 成功 | 主なエラー |
|------|------|------------|
| `POST /memos` | `201` + メモ JSON | `400` バリデーション、`500` 障害 |
| `GET /memos` | `200` + 配列（0 件は `[]`） | `500` |
| `PUT /memos/{memoId}` | `200` + 更新後メモ JSON | `400`、`404` 不存在、`500` |
| `DELETE /memos/{memoId}` | `204` ボディなし | `404`、`500` |

## 10. ローカル起動手順（骨子）

※正本の手順書は `docs/build.md`。ここでは実装時の作業順のみ。

1. DynamoDB Local を起動（`:8000`）。
2. テーブル作成（`memoId` HASH）。名前を `env.json` の `MEMOS_TABLE_NAME` と一致させる。
3. リポジトリルートで `sam build` → `sam local start-api --env-vars env.json`（`:3000`）。
4. `frontend/` で `.env` に `VITE_API_BASE_URL=http://127.0.0.1:3000` → `npm run dev`（`:5173`）。
5. ブラウザで操作検証。

Windows + Docker の場合、Lambda コンテナから見た DB URL に `host.docker.internal` を使う点に注意（Plan R-04）。
